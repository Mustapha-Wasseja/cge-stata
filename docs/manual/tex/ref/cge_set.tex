\cgeentry{cge_set}{User sets of elements, for indexes and sums}

\cgesec{Description}

\cmd{cge_set} defines a set of elements of the calibrated model, such as the
goods that are traded, the health commodities or the rural households. Its
name then serves as an index wherever the letter of a model set does: in the
definitions of user variables (\manref{cge_variable}), in user equations
(\manref{cge_equation}), in sums, and in the indexes of user parameters
(\manref{cge_parameter}). From version 0.9.1, a set of pairs records a mapping
between two sets, such as the activities and the commodities they make, for
sums and conditions.

\cgesec{Quick start}

The commodities other than services and health
\begin{stcode}
cge_set goods = c, except(com_ser com_hlt)
\end{stcode}
Government spending on them, as a user variable
\begin{stcode}
cge_variable GGOODS = sum(goods, PQ(goods) * QG(goods)), nominal
\end{stcode}
Activities paired with the commodities they make, and the value of their
output
\begin{stcode}
cge_set map(a,c) = act_agr.com_agr act_hlt.com_hlt
cge_variable VMAP = sum(map(a,c), PA(a) * QA(a)), nominal
\end{stcode}
Display the user sets
\begin{stcode}
cge_set, list
\end{stcode}

\cgesec{Syntax}

Define a set
\begin{stsyntax}
\cmdb{cge_set} \argu{name} \cmd{=} \argu{elements} [\texttt{,} \optarg{}{except}{elements}]
\end{stsyntax}
Define a set from a string variable of the data in memory (from version 0.13.0)
\begin{stsyntax}
\cmdb{cge_set} \argu{name}\texttt{,} \optarg{}{from}{varname} [\optarg{}{except}{elements}]
\end{stsyntax}
Define a set of pairs (from version 0.9.1)
\begin{stsyntax}
\cmdb{cge_set} \argu{name}\cmd{(}\argu{i}\cmd{,}\argu{j}\cmd{)} \cmd{=} \argu{e1}\cmd{.}\argu{f1} [\argu{e2}\cmd{.}\argu{f2} \dots]
\end{stsyntax}
Display or remove the user sets
\begin{stsyntax}
\cmdb{cge_set} \texttt{,} \opt{}{list}\\
\cmdb{cge_set} \texttt{,} \opt{}{clear}
\end{stsyntax}
\argu{elements} are labels of elements of the model (accounts, such as
\cmd{com_hlt}, or nests), letters of model sets (\cmd{a} activities, \cmd{c}
commodities, \cmd{f} factors, \cmd{h} households, \cmd{d} households and
enterprises, \cmd{i} institutions receiving factor income, \cmd{n} nests of
value added), and names of user sets, separated by spaces. In a standalone
model (\manref{cge_model}) there are no model sets: the elements are labels
of the set's own, of letters, digits and underscores and at most 32
characters, or names of other user sets. \argu{name} has at
most 24 characters, letters, digits and underscores; it may not be the name
of a variable, a parameter, an element, a user equation or another user set,
nor an index letter of a model set. In a set of pairs, \argu{i} and
\argu{j} are two different indexes, model set letters or user sets, and each
pair \argu{e}\cmd{.}\argu{f} joins an element of the set of \argu{i} to one of
the set of \argu{j}.

\begin{opttable}
\optgroup{Main}
\optarg{}{except}{elements} & elements left out\\
\optarg{}{from}{varname} & the elements from a string variable in memory\\
\end{opttable}

\cgesec{Options}

\begin{optdesc}
\item[\optarg{}{except}{elements}] leaves out the elements listed, given as
for the set.

\item[\optarg{}{from}{varname}] (from version 0.13.0) takes the elements
from the string variable \argu{varname} of the data in memory, in the order
they appear, each once and skipping empty values, as the account labels of a
SAM in memory. In a model from a SAM they must be elements of the model.

\item[\opt{}{list}] displays the user sets and their elements.

\item[\opt{}{clear}] removes every user set. A set that a user variable,
equation or parameter uses cannot be removed until they are.
\end{optdesc}

\cgesec{Remarks and examples}

A set whose elements are those of another, \cmd{cge_set j = i}, is the
analogue of GAMS's \cmd{alias}; the index of a set followed by digits, as
\cmd{goods2}, also runs over the same set, so that \cmd{sum(goods2, \dots)}
may appear in an equation over \cmd{goods}. An index that the domain of an
equation already controls cannot be summed over: \cmd{sum(f, \dots)} in an
equation over \cmd{f} is an error, as in GAMS, and the sum is written over
\cmd{f2}.

The SAM with a health sector is mapped and calibrated:
\stlog{set_setup}

\cgesubsec{Example 1: sets of commodities}

The elements of a set are written out in the order given, each once, without
those in \opt{}{except()}; a model set letter stands for all its elements:
\stlog{set_define}

\cgesubsec{Example 2: sums and variables over a set}

A user set's name is an index, in sums and in the definitions of variables
and equations. Government purchases of goods at market prices, and the prices
of services relative to the consumer price index, after a tariff removal:
\stlog{set_use}
A second index over the same set adds digits to its name, as in
\cmd{sum(goods, sum(goods2, ...))}.

\cgesubsec{Example 3: listing the sets}

\stlog{set_list}
User sets are saved with the model (\manref{cge_save}) and kept when it is
calibrated again.

An index that is neither a model set letter nor a user set is an error:
\stlog{set_err}

\cgesubsec{Example 4: sets of pairs}

From version 0.9.1, a set of pairs maps the elements of one set to those of
another, as a GAMS set over two indexes does: here the activities and the
commodities they make. It is not an index. A sum runs over its pairs, and in
a condition it is 1 for a pair of the set, so that a variable with two indexes
can be defined for the pairs only:
\stlog{set_pairs}

\cgesec{Stored results}

\cmd{cge_set} stores the following in \cmd{r()}:
\begin{storedres}
\resgroup{Scalars}
\res{r(N_elements)} & number of elements, or pairs, of the set defined\\
\res{r(N_sets)} & number of user sets (\opt{}{list})\\
\resgroup{Macros}
\res{r(name)} & name of the set defined\\
\res{r(elements)} & its elements\\
\end{storedres}

\cgesec{Methods and formulas}

A user set is an ordered list of labels. An expression is written out for
each element of the set of its index, and each sum over the elements of its
set (\chapref{chap:user}), so a user set changes only which elements are
written out; it adds no variables or equations of its own. A set of pairs
$P$ of the indexes $i$ and $j$ is a list of pairs of labels; a sum over it is
written out as
\begin{equation*}
\texttt{sum(}P\texttt{(}i\texttt{,}j\texttt{),}\ g\texttt{)} = \sum_{k \in I} \ \sum_{l \in J:\ (k,l) \in P} g\,[\,i = k,\ j = l\,],
\end{equation*}
and in a condition $P(k,l)$ is 1 if $(k,l) \in P$ and 0 if not. In the GAMS
program the equations are written out element by element, so user sets need
no declaration there.
