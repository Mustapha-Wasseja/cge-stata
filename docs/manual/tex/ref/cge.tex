\cgeentry{cge}{Computable general equilibrium modelling in Stata}

\cgesec{Description}

\pkg builds, calibrates and solves computable general equilibrium (CGE)
models in Stata. The built-in model uses a social accounting matrix (SAM)
and supports static simulations, recursive dynamics and perfect-foresight
runs with user-specified forward-looking equations (\manref{cge_dynamic}).
Calibrated single-country models can be linked through bilateral trade to
form a multi-region model (\manref{cge_region}).

Users can extend the built-in model or write a standalone model without a
SAM, using sets, parameters, variables, equations and nested CES or CET
blocks (\manref{cge_model}, \manref{cge_equation}, \manref{cge_nest}). The
package solves equilibrium and complementarity systems and nonlinear
optimisation problems, including models with integer or binary variables.
It also supports policy optimisation (\manref{cge_optimize}), Nash and
Stackelberg games (\manref{cge_nash}), and a library of ready-to-run examples
(\manref{cge_modlib}).

The workflow includes SAM preparation and balancing, multiplier and
structural path analysis, scenario loops, validation checks, sensitivity
analysis and reporting. A link to household survey data measures poverty,
inequality, welfare and fiscal incidence (\manref{cge_microsim}).

The built-in solvers run in Stata and Mata on Stata 13 or later. Optional,
experimental links to SciPy's SuperLU and HiGHS require Stata 16 or later
with Python and SciPy (\manref{cge_options}, \manref{cge_solve}). GAMS export
and GDX data exchange are also available (\manref{cge_gams},
\manref{cge_gdx}); solving an exported model in GAMS requires GAMS and the
selected solver.

The command \cmd{cge} displays the version of the package and its commands.

\cgesec{Remarks and examples}

\cgesubsec{The model}

The model is the standard SAM-based model of the IFPRI and PEP traditions
(Lofgren, Harris and Robinson 2002; Decaluw\'e et al.\ 2013); only the
structure of the model is taken from that literature. Its standard form has
\begin{itemize}
\item production with CES or Cobb--Douglas value added and Leontief
intermediate inputs, with an optional CES or Cobb--Douglas nest between them;
activities may produce several commodities, and a commodity may have several
producers;
\item trade through a CET function between exports and domestic sales and an
Armington CES function between imports and domestic goods;
\item households with Cobb--Douglas or linear expenditure system demand,
enterprises, the government, savings-investment and the rest of the world,
with transfers among them;
\item direct, sales, import, export and activity taxes;
\item closures for the external account, the government, savings-investment,
the numeraire and each factor.
\end{itemize}
Extensions, switched on by the layout of the SAM or by options of
\manref{cge_map} and \manref{cge_calibrate}, add VAT with input credits, public
debt, taxes on factor use and factor income, home consumption, finite export
demand, export-only commodities, margins by market, labour-market regimes, a
social health insurance fund, factor efficiency linked to health services,
health outcomes, nests of value added and the aggregation of output from
several activities. Limits that bind in some scenarios and not in others,
such as quotas and capacity limits, are complementarity conditions solved with
the model. Part~II of this manual gives every equation.

Perfect foresight solves periods together with the user's forward-looking
equations and terminal conditions; it does not supply an intertemporal
household objective. Such behaviour must be specified in user equations or
a standalone optimisation model. Regional links use each region's own SAM,
closure and shocks, together with bilateral trade data. Elasticities are
inputs supplied by the user or selected from the sourced library; the
package does not estimate them or assign defaults.

\cgesubsec{The workflow}

The built-in SAM-based model follows this workflow:
\begin{enumerate}
\item read the SAM with \manref{cge_sam}, and prepare it if needed with
\manref{cge_template}, \manref{cge_aggregate} and \manref{cge_balance};
\item assign its accounts to the roles of the model with \manref{cge_map},
which checks every cell against the flows that the model represents;
\item choose the elasticities, from studies of the country or from the library
of \manref{cge_elasticities};
\item calibrate with \manref{cge_calibrate}, which checks that the base solves
every equation, and run the checks of \manref{cge_check};
\item choose a closure with \manref{cge_closure}, change parameters or fixed
variables with \manref{cge_shock}, and solve with \manref{cge_solve}, once for
each simulation;
\item report with \manref{cge_results} and \manref{cge_report}, and save the
model and its simulations with \manref{cge_save}.
\end{enumerate}
The model is kept in Mata, not in the data in memory. Commands that load data,
such as those with a \cmd{clear} option, leave the model intact, and
\manref{cge_save} stores it with its simulations. Reading a SAM with
\manref{cge_sam} starts a new model, and mapping or calibrating again replaces
the mapping or the calibration.

\cgesubsec{The Mata library}

The commands of the package share a Mata library, compiled the first time a
command runs in a Stata session. \cmd{cge} loads it if it is not in memory and
checks that its version is that of the package. If it is not, as after an
update of the package within a session, \cmd{cge} stops with error 498;
restart Stata to load the new library.
