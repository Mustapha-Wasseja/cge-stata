\cgeentry{cge_equation}{User equations: new relations among the model's variables}

\cgesec{Description}

\cmd{cge_equation} adds an equation to the calibrated model, written in a small
language of the model's variables and parameters, for one element or for every
element of a set. With \manref{cge_variable}, which adds variables, it extends
the model without changing its code: Stata compiles the equations for its
solver, and \manref{cge_gams} writes them into the GAMS program, so that GAMS
solves the same model. \cmd{cge_equation, list} lists the user variables and
equations, and \cmd{cge_equation, clear} removes them.

\cgesec{Quick start}

Government purchases of services at \cmd{LAM} times their base level, with
\cmd{LAM} a user variable
\begin{stcode}
cge_variable LAM, value(1)
cge_equation lam: QG(com_ser) = LAM * base(QG(com_ser))
\end{stcode}
Fix \cmd{LAM} and let the scaling factor of government consumption adjust; then
raise it by 10 per cent
\begin{stcode}
cge_closure, swap(LAM GADJ)
cge_shock LAM, value(1.1)
\end{stcode}
An equation for every commodity
\begin{stcode}
cge_variable PIX(c), value(1)
cge_equation pix(c): ln(PIX(c)) = ln(PQ(c)) - ln(CPI)
\end{stcode}
An equation for the commodities with an import tariff only
\begin{stcode}
cge_variable LQM(c)$(tm(c) > 0), value(1)
cge_equation lqm(c)$(tm(c) > 0): QM(c) = LQM(c) * base(QM(c))
\end{stcode}
List the user variables and equations; remove them
\begin{stcode}
cge_equation, list
cge_equation, clear
\end{stcode}

\cgesec{Syntax}

Add an equation
\begin{stsyntax}
\cmdb{cge_equation} \argu{name}[\cmd{(}\argu{i}[\cmd{,}\argu{j}]\cmd{)}[\cmd{$(}\argu{condition}\cmd{)}]]\cmd{:}
\argu{expression} \cmd{=} \argu{expression} [\texttt{,} \optarg{}{replace}{block}]
\end{stsyntax}
Add an inequality paired with a variable (from version 0.9.0)
\begin{stsyntax}
\cmdb{cge_equation} \argu{name}[\cmd{(}\argu{i}[\cmd{,}\argu{j}]\cmd{)}[\cmd{$(}\argu{condition}\cmd{)}]]\cmd{:}
\argu{expression} \cmd{=l=}|\cmd{=g=} \argu{expression}\texttt{,}
\optarg{}{perp}{variable\textup{[}\texttt{, up}|\texttt{down}\textup{]}}
\end{stsyntax}
List the user variables and equations
\begin{stsyntax}
\cmdb{cge_equation}\texttt{,} \opt{}{list}
\end{stsyntax}
Remove the user variables and equations
\begin{stsyntax}
\cmdb{cge_equation}\texttt{,} \opt{}{clear}
\end{stsyntax}
\argu{name} has at most 24 characters, letters, digits and underscores, and
may not be the name of another user equation; a variable defined by
\manref{cge_variable} gives its name to its definition. \argu{i} is an index,
the letter of a set or the name of a user set (\manref{cge_set}), possibly
followed by digits. A condition, \cmd{$(}\argu{condition}\cmd{)}, restricts
the equation to the elements that meet it (from version 0.7.2).

\cgesec{Options}

\begin{optdesc}
\item[\optarg{}{perp}{variable\textup{[}\texttt{, up}|\texttt{down}\textup{]}}]
(from version 0.9.0) pairs an inequality with a variable fixed under the
closure, which stays at its level while the inequality has room to spare and
moves, up (the default) or down, when it binds. \argu{variable} is a variable
element, such as \cmd{RA(act_man)} or \cmd{GADJ}, or, for an equation with an
index, the variable at that index, as in \cmd{RA(a)}. See
\emph{Inequalities} below.

\item[\optarg{}{replace}{block}] (from version 0.9.3) makes the equation
take the place of the elements of the built-in equation block \argu{block},
named as in chapter~\ref{chap:equations}: the elements with the labels of its
own, or, for an equation without an index, the block without an index or the
element given, as in \cmd{replace(T2(com_agr))}. See \emph{Replacing built-in
equations} below.

\item[\opt{}{list}] lists the user variables, with their definitions or
values, and the user equations. It is the default when only a comma is given.

\item[\opt{}{clear}] removes every user variable and equation. Swaps and
constraints that involve user variables must be removed first, with
\cmd{cge_closure, swap(none)} and \cmd{cge_constraint, clear}.
\end{optdesc}

Variables are written in upper case, with as many elements as they have
indexes, and parameters in lower case. The parameters are \cmd{tm}, \cmd{te},
\cmd{tq}, \cmd{ta}, \cmd{tv}, \cmd{kappa}, \cmd{pwm}, \cmd{pwe}, \cmd{ad},
\cmd{af}, \cmd{qg}, \cmd{qinv}, \cmd{trdg}, \cmd{trdr}, \cmd{trfr},
\cmd{trgr}, \cmd{trrg}, \cmd{tshi}, \cmd{qshi}, \cmd{trshi}, \cmd{trshir},
\cmd{rd}, \cmd{rf}, \cmd{ddebt}, \cmd{fdebt}, \cmd{qlf}, \cmd{wmin},
\cmd{wref}, \cmd{sick} and \cmd{tfy}, as in \manref{cge_shock}, and \cmd{trgg},
transfers within government, and \cmd{hs0}, the base volume of health
services; \cmd{tf}, which has two indexes, and \cmd{mort} cannot be used. A
parameter takes its value in the simulation being solved, with any shock.

The indexes are \cmd{a} activities, \cmd{c} commodities, \cmd{f} factors,
\cmd{h} households, \cmd{d} households and enterprises, \cmd{i} institutions
that receive factor income and \cmd{n} nests of value added, and the names of
user sets (\manref{cge_set}), each possibly followed by digits, as in
\cmd{c2}. An equation
\argu{name}\cmd{(}\argu{i}\cmd{)} is written for every element of the set of
\argu{i}; an index that is neither that of the equation nor that of an
enclosing sum is an error. Sums may contain sums. From version 0.9.1, an
equation or a variable may have two different indexes,
\argu{name}\cmd{(}\argu{i}\cmd{,}\argu{j}\cmd{)}, and is then written for every
pair of elements of their sets (Example 7).

\cmd{^} binds most tightly and groups from the right; then come \cmd{*} and
\cmd{/}, and then \cmd{+} and \cmd{-}, which group from the left. A leading
minus sign applies after any power: \cmd{-X^2} is $-(X^2)$.

\cgesubsec{Conditions}

From version 0.7.2, a condition written \cmd{$(}\argu{condition}\cmd{)}, as
in GAMS, restricts a sum, a term, or the domain of an equation or a variable,
\argu{name}\cmd{(}\argu{i}\cmd{)$(}\argu{condition}\cmd{)}. A term is a
number, a reference such as \cmd{PQ(c)}, a function or an expression in
parentheses. Besides the terms of expressions, a condition may use
\begin{cgetable}{p{0.34\linewidth}p{0.60\linewidth}}
\toprule
Term & Meaning\\
\midrule\endhead
\bottomrule\endlastfoot
\cmd{> < >= <= == !=} & comparisons, 1 if true and 0 if not\\
\cmd{&}, \cmd{|}, \cmd{!} & and, or, not; any value other than 0 is true\\
\argu{set}\cmd{(}\argu{e}\cmd{)} & 1 if element \argu{e} belongs to a user set or a model set, as in \cmd{goods(c)}\\
\argu{map}\cmd{(}\argu{i}\cmd{,}\argu{j}\cmd{)} & 1 if the pair belongs to a set of pairs (from version 0.9.1)\\
\cmd{sameas(}\argu{i}\cmd{,} \argu{label}\cmd{)} & 1 if the element of index \argu{i} is \argu{label}\\
\cmd{ord(}\argu{i}\cmd{)} & the position of the element in its set\\
\end{cgetable}
Arithmetic is evaluated first, then comparisons, \cmd{!}, \cmd{&} and
\cmd{|}. Comparisons, \cmd{sameas()} and set membership are allowed only in
conditions.

Conditions are evaluated with the variables and parameters at their base
values, when the equation is added and when the model is calibrated again; they
choose the terms and the equation elements, which stay the same in every
scenario. A condition that is missing at the base, such as \cmd{1/tm(c) > 0}
where a tariff is 0, and a domain that no element meets are errors. Stata
reads \cmd{$}\argu{name} on a command line as a global macro, so the
condition is always written in parentheses.

\cgesubsec{Inequalities}

From version 0.9.0, a user equation may be an inequality, written as in GAMS:
\argu{lhs} \cmd{=l=} \argu{rhs}, or \cmd{<=}, for at most, and \argu{lhs}
\cmd{=g=} \argu{rhs}, or \cmd{>=}, for at least. An inequality is paired with
a variable, \cmd{perp(}\argu{variable}\cmd{)}, as an equation is paired with a
variable in a mixed complementarity problem: the variable stays at its level
while the inequality holds with room to spare, and moves, in the direction
given, when it binds, by as much as keeps it binding. The paired variable must
be fixed under the closure: a premium or rent of \manref{cge_constraint}
(\cmd{RM}, \cmd{RE}, \cmd{RA}, which go to the government), a scaling factor
such as \cmd{GADJ}, a tax adjuster that the closure fixes, or an exogenous user
variable of \manref{cge_variable}. Each element of an inequality needs its own
paired element.

Inequalities extend \manref{cge_constraint}, which bounds one model variable,
to any expression of the user language, with sets, parameters and conditions.
They are solved in the same way, in a smoothed form and then exactly in the
regimes found; \cmd{cge_constraint, list} shows them, and \manref{cge_gams}
writes them into a mixed complementarity problem. They are kept when the
model is saved, calibrated again or given another closure; one whose paired
variable a new closure frees is left out, with a note, until a closure fixes
it again. \cmd{cge_constraint, clear} keeps them; \cmd{cge_equation, clear}
removes them with the other user equations.

\cgesubsec{Lags}

From version 0.9.2, \cmd{lag(}\argu{VAR}\cmd{)} is the value of a variable in
the period before, and \cmd{lag(}\argu{VAR}\cmd{(}\argu{e}\cmd{),} \argu{k}\cmd{)}
its value $k$ periods before, for $k$ from 1 to 4, as \argu{VAR}\cmd{(t-1)} and
\argu{VAR}\cmd{(t-}\argu{k}\cmd{)} in a GAMS model indexed by time. In a
period of a dynamic run (\manref{cge_dynamic}), the values are those of the
periods solved before it, and of the base before the first period; within the
period they are given, as the capital stock is, so a lag adds no variable to
the system. In a static simulation the period before is the base, and
\cmd{lag(}\argu{VAR}\cmd{)} is the base value of \argu{VAR}. Lags carry stocks
and partial adjustment that the model does not update itself from one period
to the next (Example 8). A defined variable may not refer to its own lag,
since its base value would depend on itself: it is given \opt{}{value()} and an
equation instead.

From version 0.10.2, \cmd{lead(}\argu{VAR}\cmd{)} and
\cmd{lead(}\argu{VAR}\cmd{(}\argu{e}\cmd{),} \argu{k}\cmd{)} are the values of
later periods, \argu{VAR}\cmd{(t+1)} and \argu{VAR}\cmd{(t+}\argu{k}\cmd{)}, in
a run with perfect foresight (\manref{cge_dynamic}, \cmd{foresight}), which
solves the periods together: a lag or a lead is then a variable of another
period. Beyond the last period a lead follows the run's \cmd{terminal()}
condition; in a static simulation it is the base value, and a recursive run
with leads is an error. \cmd{tperiod} is the period, and \cmd{tfirst} and
\cmd{tlast} are 1 in the first and in the last period of a dynamic run and 0
otherwise (all three are 0 in a static simulation), so that
\cmd{ifthen(tlast, }\argu{x}\cmd{, }\argu{y}\cmd{)} gives the last period an
equation of its own, a terminal condition. Conditions (\cmd{\$}) are
evaluated once, at the base, and may not use the period.

\cgesubsec{Replacing built-in equations}

From version 0.9.3, \cmd{replace(}\argu{block}\cmd{)} makes an equation take
the place of elements of a built-in equation block, as a GAMS modeller would
edit an equation of the model. An equation with an index replaces the elements
of the block with the labels of its own; its indexes run over the sets of the
block, or over user sets within them, in the same order. An equation without an
index replaces a block without an index, or the element given,
\cmd{replace(}\argu{block}\cmd{(}\argu{e}\cmd{))}. From version 0.11.0 an
equation with an index may give a label beside the index,
\cmd{replace(Q4(lab, a))}: the elements of \eqref{eq:Q4} for labour and each
activity. \manref{cge_nest} writes its blocks so. The replaced elements leave the
system, which therefore stays square, and the closure is unchanged.
Section~\ref{sec:userreplace} lists the blocks that may be replaced. Those
with derivatives coded in the package cannot be: equations \eqref{eq:P7},
\eqref{eq:P8}, \eqref{eq:P9}, \eqref{eq:I1}, \eqref{eq:I8}, \eqref{eq:I9},
\eqref{eq:S1}, \eqref{eq:S2}, \eqref{eq:S3} and \eqref{eq:S5}. A replacement must keep the accounting of
the model consistent: Walras's law, whose residual \cmd{WALRAS} every
simulation reports, shows when it does not (Example 9).

\cgesubsec{Functions and macros}

From version 0.9.7, expressions may use the functions of GAMS that a square
system solves, \cmd{max()}, \cmd{min()}, \cmd{abs()}, \cmd{sqr()},
\cmd{log10()} and \cmd{ifthen()}, the products and extremes over sets,
\cmd{prod()}, \cmd{smax()} and \cmd{smin()}, the size of a set, \cmd{card()},
and macros (\manref{cge_macro}), as GAMS's \cmd{\$macro}. \cmd{prod()},
\cmd{smax()} and \cmd{smin()} take the domains of \cmd{sum()}: one index, two
indexes, a set of pairs, and a condition. A product over a set that no element
meets is 1, as an empty sum is 0; a maximum or minimum over one is an error
(459), since GAMS's would be $-\infty$ or $+\infty$, no number a model can
use. Over two indexes or a set of pairs, the elements of the first index
without a pair are left out.

The condition of \cmd{ifthen()} is a condition as above, evaluated at the
current values of the parameters and lags, so that a shock to a parameter
switches it. It may not use variables: a switch on endogenous variables makes
the system discontinuous, and GAMS's CNS and MCP models refuse it. Such a
switch is an inequality paired with a variable (\emph{Inequalities} above),
which GAMS solves as a complementarity problem.

\cmd{max()}, \cmd{min()} and \cmd{abs()} are continuous with a kink where two
arguments are equal, or the argument of \cmd{abs()} is zero. The solver uses
the derivative of the first of the equal arguments there, and 0 for
\cmd{abs()}; a model whose solution lies on a kink may need more iterations,
as it may in GAMS. Example 10 uses each function and a macro.

\cgesubsec{Equations and the closure}

Each equation element needs a free variable, so that the closure stays square:
a variable added by \cmd{cge_variable} with \opt{}{value()}, or a variable that
a swap frees. In the example below, the equation determines the new variable
\cmd{LAM}; the swap then fixes \cmd{LAM} and frees the scaling factor of
government consumption, so that \cmd{GADJ} adjusts to satisfy the equation. The
base need not satisfy a new equation: if it does not, \cmd{cge_equation} says
so, and the equation then acts as a shock, moving the solution from the base.

User equations are saved with the model, compiled again when the model is
calibrated again, and solved in every simulation, dynamic run and sensitivity
draw.

\cgesec{Methods and formulas}

An equation $\ell(x) = r(x)$ with index $i$ is written out for every element
$e$ of the set of $i$, with $i$ replaced by $e$ where it is an argument of a
variable or a parameter; each \cmd{sum(}$j$\cmd{,} $\cdot$\cmd{)} is written
out in the same way over the elements of the set of $j$, inner sums first, so
that
\begin{equation*}
\texttt{sum(}j\texttt{,}\ g\texttt{)} = \sum_{k \in J} g\,[\,j = k\,],
\end{equation*}
where $J$ is the set of index $j$ and $g\,[\,j = k\,]$ is $g$ with $j$ replaced by
$k$. With a condition $q$ (from version 0.7.2),
\begin{equation*}
\texttt{sum(}j\texttt{\$(}q\texttt{),}\ g\texttt{)} = \sum_{k \in J:\ q[\,j = k\,](x^0,\,\theta^0) \neq 0} g\,[\,j = k\,],
\end{equation*}
with $q$ evaluated at the base point $x^0$ and the base parameters $\theta^0$;
a conditional term $g\texttt{\$(}q\texttt{)}$ is $g$ where $q(x^0, \theta^0) \neq 0$
and 0 elsewhere, and an equation with a condition is written out only for the
elements $e$ with $q[\,i = e\,](x^0, \theta^0) \neq 0$. Sums are written out from
the outside in, each element substituted before the sums within, so that an
inner condition may use the index of an enclosing sum. From version 0.9.1, a
sum over two indexes and a sum over a set of pairs $P$ are sums over one index
at a time,
\begin{equation*}
\texttt{sum((}j,k\texttt{)\$(}q\texttt{),}\ g\texttt{)} = \texttt{sum(}j\texttt{, sum(}k\texttt{\$(}q\texttt{),}\ g\texttt{))}, \qquad
\texttt{sum(}P\texttt{(}j,k\texttt{),}\ g\texttt{)} = \texttt{sum(}j\texttt{, sum(}k\texttt{\$(}P\texttt{(}j,k\texttt{)),}\ g\texttt{))},
\end{equation*}
and an equation with two indexes is written out for every pair of elements
that meets its condition.
Each side is then compiled to postfix order, with numbers, variables (as
positions in the stacked vector of variables), parameters, operators and
functions, and \cmd{base()} replaced by the number it denotes. The solver
evaluates both sides at each point, with the parameters of the simulation, and
the equation element is
\begin{equation*}
\ell_e(x) - r_e(x) = 0,
\end{equation*}
a row of the block \cmd{U} of the system. Its derivatives are exact, from
version 0.7.0: the postfix form of each side is differentiated in forward
mode, with respect to the variables that the equation element contains
(section~\ref{sec:jacobian}).
An inequality $\ell(x) \le r(x)$ paired with $v$, fixed at $\bar v$ and moving
up, adds a slack variable $s = r(x) - \ell(x)$, defined by a user equation and
named \cmd{_S_}\argu{name}, and the constraint
\begin{equation*}
s \ge 0, \qquad v - \bar v \ge 0, \qquad s\,(v - \bar v) = 0,
\end{equation*}
solved as the constraints of \manref{cge_constraint} are
(chapter~\ref{chap:constraints}); with \cmd{=g=}, $s = \ell(x) - r(x)$, and
moving down, $\bar v - v \ge 0$. A defined user variable $u = e(x)$ with a
lower bound $b$ becomes $u = e(x) + a$, with an adjuster $a$ fixed at zero
paired with the constraint $u \ge b$, so that $u = \max(b, e(x))$; an upper
bound subtracts a second adjuster.

A lagged value $\texttt{lag(}v\texttt{,}\ k\texttt{)}$ (from version 0.9.2) is a
number within a period: $v_{t-k}$, the solution of the period $k$ before in a
dynamic run, with $v_{t-k} = v^0$ for $t - k$ before the first period, and $v^0$
in a static simulation. Its derivative is zero.

An equation that replaces the element $e$ of a block $B$ (from version 0.9.3)
removes the row $B_e$ from the system, $\ell_B(x)_e - r_B(x)_e = 0$, and adds its
own; in the GAMS program, the parameter \cmd{XRP(}$B$\cmd{, }$e$\cmd{)} is 1, and
the equations of block $B$ leave out the element.

A product, maximum or minimum over a set (from version 0.9.7) is written out
as the sum is, with $*$ or as the arguments of \cmd{max()} or \cmd{min()},
\begin{equation*}
\texttt{prod(}j\texttt{,}\ g\texttt{)} = \prod_{k \in J} g\,[\,j = k\,], \qquad
\texttt{smax(}j\texttt{,}\ g\texttt{)} = \max_{k \in J} g\,[\,j = k\,],
\end{equation*}
and \cmd{card(}$J$\cmd{)} is the number $|J|$. A function $\phi$ of the
arguments $a_1, \dots, a_m$ has the derivative
\begin{equation*}
\frac{\partial \phi}{\partial x} = \sum_{l} \frac{\partial \phi}{\partial a_l}\,\frac{\partial a_l}{\partial x},
\end{equation*}
with $\partial \max / \partial a_l$ equal to 1 for the first argument at the
maximum and 0 for the others (likewise for \cmd{min()} and the branch that
\cmd{ifthen()} takes), $\partial |a| / \partial a = \mathrm{sign}(a)$,
$\partial a^2 / \partial a = 2a$ and $\partial \log_{10} a / \partial a = 1 /
(a \ln 10)$. A macro is replaced by its expression, each argument substituted
for its parameter, before the indexes are written out, so a macro adds nothing
to the system; \manref{cge_macro} gives the rules.

GAMS differentiates the same equations itself.
