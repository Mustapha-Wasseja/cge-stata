# Contributing to cge-stata

These conventions apply to every change, whoever or whatever prepares it.

## Model changes

1. Change [docs/model_spec.md](docs/model_spec.md) first.
2. Implement the change in the Python reference model (`reference/`) and in the
   Stata/Mata code (`ado/`) in the same pull request.
3. Add or update tests in both suites. A model change is complete only when the
   validation checks in model_spec.md, Section 8, pass in both implementations.

## Stata code

- Stata 13 compatibility: every ado-file starts with `version 13.0`; use only
  Mata functions available in Stata 13; keep model arrays in Mata.
- Command names start with `cge_`. Each command has an `.sthlp` help file and is
  listed in `cge.pkg`. Files other than `.ado` and `.sthlp` (for example
  `cge_mata.mata` and data files) need an `F` line in `cge.pkg`, or
  `net install` will not install them.
- Model code is in `ado/cge_mata.mata`; ado-files are thin wrappers that call it.
  After editing the Mata file, run `clear all` so that the new version is
  loaded.
- File header, as in the existing files:

  ```stata
  *! cge_name.ado  v0.0.1  YYYY-MM-DD
  *! cge-stata: one-line purpose
  *! One-line description
  *!
  *! Author: Mustapha Wasseja
  *! Requires: Stata 13+
  ```

## Tests

- Python reference tests: `python -m pytest reference/tests` (also run in
  continuous integration).
- Stata tests (Windows, local Stata installation):
  `powershell -ExecutionPolicy Bypass -File tools\run_stata_tests.ps1`.
- Stata cannot run in continuous integration. Changes to Stata code must be run
  through the local Stata suite before they are merged into `main`.

## Data

- Commit only the synthetic SAM generated by `reference/synthetic_sam.py`, or
  data whose licence explicitly allows redistribution.
- Never commit country SAMs, survey data or confidential statistical-office
  files.
- Never commit Stata logs (`*.log`, `*.smcl`). Batch logs print the Stata
  licence details. They are excluded by `.gitignore`.

## Commits and pull requests

- Author every commit as
  `Mustapha Wasseja <51772479+Mustapha-Wasseja@users.noreply.github.com>`.
  Continuous integration rejects commits with any other author.
- Do not add `Co-authored-by` trailers, tool attribution lines or generated-by
  notices to commits, pull requests, issues, code comments or documentation.
- Work on branches named `dev/<topic>` and merge into `main` once both test
  suites pass.
- Write commit messages in the imperative mood, with a short summary line and,
  where useful, a body explaining what changed and how it was tested.
